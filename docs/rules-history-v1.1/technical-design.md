# 技术方案：规则与历史导入导出

日期：2026-11-11 · 待评审，未实现。依据：[PRD](prd.md)。本文的类型名和存储结构均为拟议设计，不是现有接口。

## 1. 当前基础与接入点

当前 HistoryStore 持有 SQLiteDatabase、PayloadStore 和共享 NSLock，insertOrTouch 命中哈希时会更新来源及时间。CaptureMonitor 每 400ms 观察变化，后台串行队列解码。PrivacyGate 统一决定是否采集。ContentHash 执行现有文本、像素、文件去重。片段库已迁移至 user_version=2，不能按旧文档的版本 1 设计升级。

Domain 新增 AppTagRule、IgnoreRule、RuleSnapshot、HistoryArchive、ImportPlan 等纯模型；不访问剪切板。Features/Rules 负责编辑和测试，Features/Transfer 负责导入导出状态机。Storage 增加 RuleStore、ArchiveRepository 和批量提交接口；AppModel 装配；Platform 封装系统文件选择器和隔离的正则执行服务。

## 2. 规则流水线

先执行既有 PrivacyGate，再读取必要类型；在原文截断前，将文本交给正则服务。规则结果汇入 PrivacyDecision（拟增 matchedIgnoreRule、ruleEvaluationUnavailable），仍由 PrivacyGate 返回是否允许，采集层不复制隐私规则。允许后才构建完整 CapturedClipboard、分配标签并入库。规则输入只能来自剪切板真实文本表示，不能使用文件条目的 plainText 文件名。

每次变化固定规则版本快照；最终回调前校验 changeCount、规则版本与既有隐私状态，过期则丢弃，不把旧文本关联到新来源。规则变更先完成持久化再发布新快照。哈希命中不更新标签，新插入在同一事务写入标签快照。

## 3. 正则隔离与预算

拟使用系统 Foundation 正则能力，但同步正则不承诺可被 Swift Task.cancel 中断；不能用 Dispatch 超时后继续放任失控匹配。拟增加随应用打包的独立 XPC worker，主进程不执行用户表达式。worker 串行编译和匹配，测试按钮走同一路径。通过独立启动代次管理进程；到期终止 worker、丢弃过期回调，重启前要求解除异常规则。XPC 打包、硬化运行时和终止能力必须先做 macOS 技术验证，不能在验证前声称可行。若不可可靠终止，则暂停本功能落地并重新选择有确定计算预算的引擎，不能降级成主进程无界匹配。

拟议限额：50 条规则、单表达式 4096 UTF-8 字节、完整输入 8MiB、整次 worker 请求 100ms（含全部规则）；只保留一个在途请求，繁忙变化直接拒绝并提示检查繁忙，不无限排队。输入超限在发送前拒绝整条，不只匹配前缀。以上是待基准测试的设计值，不是实测结果。超时/崩溃/无效持久化规则令文本采集进入受阻状态，用户修复或禁用后恢复；不能把服务失败视作未命中。worker 不输出正文、表达式或匹配内容到日志。

## 4. 拟议存储迁移

只描述方案，不执行 SQL。数据库从版本 2 在单事务升级到 3；保留 items 主键与既有片段表。新增 app_tag_rules（bundle_id 唯一、label、enabled、revision）、ignore_rules（id、name、pattern、enabled、position、revision）以及 item_labels（item_id 主键外键级联、label、normalized_label）。标签使用独立关联表，避免修改核心 items 列。标签是快照，不外键引用可删除的规则。版本大于支持值拒绝打开，迁移失败回滚，不把版本写回 1 或 2。

拟新增 archive_import_jobs 记录导入批次和负载生命周期；该表与升级须在实现前评审。方案不含现有库实际迁移。规则删除不能级联删除历史。查询失败 throw，视图保留最后成功快照。标签缓存与规则保存成功后才刷新。

## 5. JSON 契约

顶层 format="clipboardassistant.history"、formatVersion=1、exportedAt（UTC ISO 8601）、items。应用数据库版本不充当备份格式版本。条目包含 kind、plainText、sourceBundleID、sourceName、createdAt、lastUsedAt、pinned、label、byteSize、payloadOversize、可选 imageWidth/imageHeight、representations。representation 含白名单 UTI 与 Base64 data；文件引用为专用 files 数组（path、name、size、modifiedAt），禁止外部 payloadPath。导出可带原 ID 仅供排错，但导入不采用。

文本/富文本和图片保存实际允许的类型，未知 UTI 整批拒绝。缩略图导入后重新生成。文件元数据参与哈希但不 stat 文件，不访问网络路径；文件粘贴仍遵守既有失效提示。混合条目哈希构造沿用 CaptureBuilder 的实际组合顺序，实施前补固定测试向量，不能自行拼接一种新算法。

完整条目按现有 ContentHash 重算。预览使用带命名空间的 SHA-256：archive-preview-v1 + kind + 预览文本 + 原 byteSize + 尺寸；长度前缀编码消除拼接歧义。只保证相同预览快照重复导入幂等，无法证明原文相同，不与现有完整哈希合并。此限制在确认页说明。

拟议资源限额：文件 512MiB、解码后负载合计 256MiB、最多 10000 条、单条文本完整负载 1MiB、图片 10MiB；元数据字符串逐字段限长，时间须有限且在 1970 至导入时刻后 24 小时内，非法时间拒绝而非自动修正。图片验证实际解码尺寸、像素数（上限 40MP），避免解压炸弹。超限备份不得生成成功文件；应缩小范围。解析流式逐条到临时区，不把 Base64 与解码负载全部同时常驻内存。所有数值限额待实际性能验收定稿。

## 6. 一致性、事务与崩溃恢复

导出在短锁内抓取有序元数据及负载引用，使用读取租约阻止其负载被并发清理；不长时间持锁做编码。流式写目标目录临时文件，成功后原子替换，失败取消删除临时文件并释放租约。获取不到完整负载则失败，不悄悄降级成预览。备份中不存机器内部负载路径。

导入状态：idle → validating → preview → committing → result；校验中可取消，提交事务开始后禁用取消并解释“正在完成导入”。先解析到受控临时目录，所有路径由本机生成 UUID，拒绝路径穿越、重复字段、非法 Base64 和不支持的表示。预览固定数据库修订号与保留设置版本。

确认时加存储写锁，重新核对版本，变化则退回预览。去重、保留计划、插入和淘汰行在同一数据库事务。不能循环调用 insertOrTouch，因为会覆盖本地重复项元数据并逐条触发保留。重用 RetentionPolicy 的实际计算，在写入前得出确定计划；新增又将淘汰的条目不必写出负载，但统计单列。

负载先写入 staging/<jobID> 并完成落盘，再移动到 UUID 最终目录；此时尚不发布条目。数据库事务登记最终引用、job 状态和待清理列表后提交。失败回滚并清理仅本批新目录；不能删除原有负载。成功提交才删除淘汰条目的文件，失败进入可重试清理队列。

启动恢复依据数据库已提交引用及批次记录：未提交的 staging/孤立批次可回收，已提交的最终负载保留，待删文件只在无数据库引用时清理。使用 SQLite WAL 并验证 fsync/目录持久性；跨文件系统不假设 rename 原子。提交前负载在同一应用支持卷中完成移动。崩溃注入覆盖写文件、移动、提交前后及清理阶段。

## 7. 隐私与界面

规则内容进数据库，不写 UserDefaults。过滤文本、测试文本和归档内容不入日志、诊断。导出明文提示不作为阻碍正常操作的额外审批。导入跳过采集规则是用户主动恢复语义，仅限导入入口，不能复用来绕过实时采集过滤。

面板内导出范围来自当次筛选快照；设置页固定全部。导入预览采用独立表单，禁止路由到历史清空快捷键。保存错误保留输入；确认淘汰现有历史的勾选在重新预览后重置。文案使用 L10n.text，中英文及辅助功能名称齐全。

## 8. 实施顺序与验证

先验证正则隔离和流式解析可行性；再实现纯模型/规则合约与测试；评审数据库升级；完成规则存储和采集接入；完成归档编解码及批量事务；最后接界面与错误恢复。新增 Swift 文件必须登记 Xcode 工程，测试加入 ClipboardAssistantTests。

测试覆盖标签快照、规则错误与超限、隐私不回退、哈希固定向量、JSON 往返与 TXT、恶意输入、重复导入、置顶顺序、计划失效、并发导出租约、磁盘满、SQLite 失败和每个崩溃恢复点。全量 xcodebuild test 与 PRD 验收通过才发布。

## 9. 评审门槛

产品需确认 PRD 默认选择；技术需确认正则 worker 的可靠终止、限额、流式编码方式和备份语义。数据库新增表和版本升级在实际修改前另行确认。本次只写文档，无 schema 或依赖变更。
