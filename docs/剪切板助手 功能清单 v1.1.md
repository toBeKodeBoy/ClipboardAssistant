# 剪切板助手 · 功能清单 v1.1

| 项 | 内容 |
|---|---|
| 对照 | `docs/requirements.md` 第 10 节、第 13 节；`docs/technical-design.md` 第 13 节 |
| 范围 | 片段库、规则、历史导入导出、OCR 文字识别搜索、正则表达式搜索 |
| 状态 | 历史规划快照；当前实现状态见下方说明 |

> 本清单保留原始规划措辞，下文「未做」和数据结构描述属于备份时的历史状态。当前片段库、历史 JSON/TXT 导出及 JSON 去重导入已实现；规则与标签未提供，OCR 和正则搜索未实现。实现详情见 `snippets-v1.1/implementation.md` 和 `rules-history-v1.1/validation.md`。

备份时库只有 `items` 和 `representations`，`user_version` 固定为 1。没有片段表、规则表，也没有历史导入导出。关于页的诊断 JSON 只含版本、权限、条数和数据库大小，不是历史导出。

片段库、规则、导入导出、OCR 文字识别搜索和正则表达式搜索都写在需求第 10 节。没写明的入口、引擎和匹配细节不在这里补。需求第 13 节里标成 v1.2 或不纳入的能力，不属于这一版。

## 1. 片段库

| 功能 | 状态 | 需求写了什么 |
|---|---|---|
| 手动保存 | 未做 | 用户主动把内容存成片段。没写是从历史保存、从当前剪切板保存，还是两者都要 |
| 分组 | 未做 | 片段可以分组。没写分组是否嵌套、如何排序、空分组怎么处理 |
| 关键字触发 | 未做 | 片段可以用关键字触发。没写是输入时替换、在面板里匹配，还是单独的菜单项 |
| 变量与表单 | 未做 | 第 3 节写明放到 v1.1。第 10 节的里程碑没有再列这两项。变量语法和表单字段都没写 |

## 2. 规则

| 功能 | 状态 | 需求写了什么 |
|---|---|---|
| 按来源应用自动打标签 | 未做 | 采集时按来源应用打标签。没写标签名是否等于应用名、能否手改、是否进入搜索和筛选 |
| 正则忽略 | 未做 | 正则可配置，命中则不入库。验证码样式是例子。默认不忽略 |

## 3. 历史导入导出

| 功能 | 状态 | 需求写了什么 |
|---|---|---|
| 导出为 JSON | 未做 | 导出的是历史。没写是否包含图片负载、文件引用、置顶和来源应用 |
| 导出为纯文本 | 未做 | 与 JSON 并列的另一种导出。没写一条一个文件，还是一个文件里多条 |
| 导入时去重 | 未做 | 导入时去重。没写去重键。v1 历史用内容哈希去重，需求没有说导入沿用同一把钥匙 |

## 4. 数据

设计第 13 节只写了两句：v1.1 可以新增片段表和规则表，不改现有 `items` 的主键。表的列没有写。同步用的修改时间和同步状态不属于这一版。识别出的文字要不要单独落库，设计没写。

## 5. 搜索

v1 的搜索是包含匹配，匹配纯文本、标题和来源应用名，英文不区分大小写。下面两项都还没做，也不改变这条现有行为。

| 功能 | 状态 | 写了什么 |
|---|---|---|
| OCR 文字识别搜索 | 未做 | 历史图片里的文字可以拿来搜索。纯文本历史不靠 OCR。识别引擎、语言、入库时识别还是搜索时识别、结果存哪里，都没写。需求仍写明不申请屏幕录制，理由是 v1 不做截图 OCR；这次是识别已经入库的图片，不是截屏 |
| 正则表达式搜索 | 未做 | 用正则在已有历史里搜索。和上面的「正则忽略」不是一回事：忽略是采集时不入库，搜索是在已经记下的条目里匹配。没写匹配哪些字段、是否区分大小写、表达式不合法时怎么提示 |
